# Ripple

Paste a headline, an article, or a link. Ripple turns it into a short narrated explainer video about how the news ripples through markets, then lets you ask follow-up questions that each become a new video.

## Running it

```bash
npm install
echo "FAL_KEY=your-key" > .env.local
npm run dev
```

Open http://localhost:3000. Everything runs through fal: the script is written by Claude Sonnet 4.5 via fal's OpenRouter endpoint (override with `LLM_MODEL`), and the scenes are generated by MiniMax H3 Max. FFmpeg ships with the `ffmpeg-static` package, so there is nothing else to install.

## How it works

1. **Read the source.** Links are fetched on the server and cleaned with Readability. Paywalled pages fall back to their headline, and the model is told exactly what it could and couldn't read.
2. **Write the script.** One call to the language model returns a JSON plan: the analysis, a visual metaphor, a look, a style bible, a title, a one-line takeaway, three follow-up questions, and the scenes. Each scene has its narration, a shot description, and a sound cue. The plan is validated with Zod; if it doesn't parse or a rule is broken (for example, a narration too short for its clip), the error goes back to the model for one retry.
3. **Generate the scenes.** Every scene is a separate 5 to 15 second clip from `minimax/h3-max/reference-to-video` at 480p, 4:3. All scenes generate in parallel, and the card shows how many are ready.
4. **Join them.** The clips are concatenated on our server with FFmpeg, which takes a few seconds, then uploaded and streamed back to the chat.

Follow-ups send the whole conversation back, including earlier scripts, so a follow-up video reuses the same metaphor and recurring elements instead of starting over.

## Prompt design

The prompts live in two places: the script-writing instructions in [`src/lib/prompts.ts`](src/lib/prompts.ts), and the per-scene video prompt assembly in [`src/lib/explainer.ts`](src/lib/explainer.ts). The split is deliberate: the language model decides *what to say and show*, and code adds everything that must be identical in every clip, so it can't drift.

**Analysis before video.** The model writes its market analysis first: what happened, the transmission chain from event to assets, who wins and loses, the strongest counter-argument, and the concepts a non-expert needs. The video is planned from that analysis, not from the headline directly.

**Grounded facts.** Story-specific facts (names, figures, dates, who said what) may only come from the source. The model's own knowledge is for how markets work in general. It never names a current officeholder unless the source does, and it says so when something is unknown.

**Length is earned.** The only hard limit is 180 seconds. The model lists the ideas a non-expert needs, gives each one a scene, and cuts anything that doesn't change understanding, so a one-line headline makes a short video. Scene durations are then recomputed from the narration's word count, because the video model stretches or repeats speech to fill a clip that's too long.

**Story structure.** Hook, mechanism, impact, then uncertainty and what to watch. Each scene is one or two complete sentences, with jargon explained in the same breath and numbers written the way they're spoken.

**Consistency across independent clips.** Each clip is generated with no memory of the others, so:
- A *style bible* (lens, palette, lighting) is prepended to every metaphor scene, and one *look* (cinematic footage or a 3D clay miniature world) is used for the whole video.
- *Recurring elements* are described once, precisely, and copied word for word into every scene they appear in.
- The *narrator* comes from a reference audio clip (`assets/narrator-voice.mp3`) passed to every scene, plus a fixed seed, so the voice stays the same across scenes and videos.

**Writing a prompt the video model can render.**
- One subject, one action, one camera move per scene, in the order subject, setting, camera, lighting. Longer scenes are paced in two timed blocks.
- Props that invite garbled text (documents, screens, signs, charts, dials) are banned from metaphor scenes, and faces are never shown in close-up.
- Each scene ends with a targeted negative line ("No other text, garbled characters, misspellings…"), which H3 follows well.
- Sound is directed too: a quiet ambient cue under the voice, and never music, since music would jump at every cut.

**Motion graphics without hallucinated charts.** When a diagram explains better than the metaphor, the model picks one of five types (cards with arrows, a cause-and-effect chain, a trend line, a two-bar comparison, a gauge) and fills in only labels and directions. Code turns that into a tightly specified prompt. Graphics show direction only, never magnitude, and numbers appear only if they're in the source.

**Captions.** TikTok-style captions are burned in by the video model itself. Code splits the narration into short chunks of up to four words, at phrase boundaries, and gives the model the exact text in order, with a fixed size, position, and color. Video models render quoted text far more reliably than free-form text.

## Interface

- **Landing page.** One input, four suggested stories, and a gallery of finished examples that play in place or open as a chat.
- **Video card.** While the script is being written, the card shows what's happening ("Retrieving the link…", "Writing the script…", "Generating scenes · 2 of 5 ready", "Joining scenes…"). It then shows the video, a title, a one-sentence takeaway, and a timestamped transcript.
- **Follow-ups.** Three suggested questions appear under each video as buttons, and the input stays open for your own.
- **Honesty.** A footer note says these are educational explainers, not financial advice, and that videos are AI-generated.

## Project layout

| Path | What it does |
| --- | --- |
| `src/lib/prompts.ts` | Instructions for the script-writing model |
| `src/lib/explainer.ts` | Plan schema, length rules, captions, diagrams, and per-scene prompt assembly |
| `src/server/generate-explainer.ts` | Calls the language model, validates the plan, retries once |
| `src/server/retrieve-url.ts` | Fetches and cleans linked articles |
| `src/server/generate-video.ts` | Generates scenes in parallel on fal |
| `src/server/join-videos.ts` | Joins the clips with FFmpeg |
| `src/routes/api/chat.ts` | Streams progress and results to the chat |
| `src/routes/index.tsx` | Landing page and chat |
| `src/components/explainer-video-card.tsx` | The video card in the chat |
| `src/components/example-card.tsx` | The gallery card on the landing page |

## Known limits

- A video takes a minute or two, because each clip is generated in full before they're joined. Showing scenes as they arrive would make it feel faster.
- The video model draws the captions and graphic labels, so an occasional garbled word can still slip through.
- Narration timing is estimated from word count, so a scene can end with a brief pause or a slightly rushed line.
